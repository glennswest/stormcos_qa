## 1. Dependencies

- **rustls-webpki** (lock 0.103.15; reached via reqwest `rustls-tls`).
  Fedora 44 moved to 0.103.16 on 2026-10-20 for RUSTSEC-2026-0381, -0382 and
  -0383 (also CVE-2026-111943, tied to the eMudhra intermediate CA
  compromise), with webpki-roots / webpki-root-certs 1.0.10
  ([Fedora update](https://linuxsecurity.com/advisories/fedora/rust-rustls-webpki-fedora-44-2026-8f36b2341e)).
  Severity and affected ranges not read. Exposure looks low: qa-test verifies
  the apiserver against the ServiceAccount `ca.crt` only, but webpki-roots is
  in the lock, so a bump is cheap. Filed as an issue.
- **russh** (lock 0.63.3). Vendor fixed zero-value parsing DoS and an
  availability issue in 0.65.0 (CVE-2026-116775, CVE-2026-116696, listed low;
  [vuln.today](https://vuln.today/tag/russh)). Earlier CVEs (0.60.1, 0.60.3,
  0.61.0, 0.62.4, 0.62.5) are all fixed in 0.63.3. This closes the
  "truncated entries" question from 2026-10-13 only partly: the 0.65.0 items
  are the new ones. qa-test uses russh as a client against our own VMs, so
  the exposure is a hostile server; low. Filed with the rustls-webpki bump.
- **tokio 1.53.0, reqwest 0.12.28, hyper 1.11.1, rusqlite 0.37.0 /
  libsqlite3-sys 0.35.0, ring 0.17.14, aws-lc-sys 0.45.0**: nothing found for
  October/November. (SQLite FTS5/session CVEs from the last pass remain
  unexposed: the workload uses neither.)
